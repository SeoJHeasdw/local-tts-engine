# 아키텍처와 연동 계약

## 책임 분리

```text
udemy-agent                           local-tts-engine
강의 대본·슬라이드 UI ── 제작 입력 ─▶ 모델 로드·음성 생성
캡처 실행 코드        ── 화면 프레임 ─▶ 타임라인·자막·완성 영상 보관
```

`local-tts-engine`은 제작 앱, 개인 음성 원본, TTS 작업, 자막·타임라인과 완성
영상을 책임진다. `udemy-agent`에는 강의 대본, 슬라이드 UI와 기존 캡처 실행
코드만 남긴다. 앱은 `export_udemy.py`로 타임라인 계약을 넘긴 뒤
`captions.mjs`와 `capture.mjs`를 각각 실행한다. 산출물 위치는 로컬 설정으로
지정한다. `narration.mjs`는 과거 명령의 하위 호환만 담당한다.

## 현행 제작 입력 고정과 검사

음성 프로필은 AGENTS의 승인된 Qwen3-TTS + jaeho-ko-r16-v1 0.60을 유지한다.
앱은 음성 생성 전에 `udemy-agent/deck/tools/production.mjs`로 화면·대본·자료·
장표 순서를 한 번에 복사하고, 전후 해시·선택 ID·스텝/BEATS·선택 챕터 린터를
확인한다. 영상이면 타입 검사와 정적 빌드까지 수행한다.

입력 복사·정합성 검사·빌드는 `scripts/prepare-production-input.mjs`의 별도
Node 프로세스에서 실행한다. Electron 메인 이벤트 루프를 막지 않아 준비 중에도
중지 요청을 받는다. 챕터 레슨 목록을 다시 읽는 Python도 작업 프로세스로 추적한다.
중지는 해당 작업의 프로세스 그룹에 SIGTERM, 3초 뒤 남은 그룹에 SIGKILL을 보낸다.
임시 입력 정리가 끝나야 실패·중지·완료 상태로 바뀌며 다음 제작을 허용한다.
하위 프로세스 로그는 앱과 실행 터미널에 함께 출력하고, 실패 메시지는 stderr의
마지막 오류를 포함한다. 실패 시 앱의 상세 기록을 펼치고 중지 버튼과 진행 표시를 숨긴다.

`.production-input/deck`를 TTS의 `--source-project` 아래 deck으로 사용하고,
export/captions/capture도 그 복사본의 설정과 도구를 쓴다. 제작 중 원본의
narration.config를 바꾸지 않는다. 챕터를 여러 영상으로 나눌 때도 같은 입력을 사용한다.
복사 도중 소스가 변경되거나 선택한 번호의 ID가 달라지면 생성 전에 중단한다.

`production-input.json`의 `sourceContract`를 음성 manifest → export timeline →
validation-report로 보존한다. 캡처 사이트 계약과 비교한 뒤 실제 화면 ID·번호·
스텝을 확인한다. ID 속성은 생성 번들에만 추가하며 원본 강의 덱은 변경하지 않는다.
작업 완료·실패·취소 때 임시 입력을 정리하고 검수 보고서와 소스 식별값은 결과에 남긴다.

촬영 전 `lessons --timeline`으로 실제 체류 시간과 자동 재생 영상의 videoBeats를
검사해 `lesson-review.json`을 남긴다. 구도·회상·CV는 검토 후보이고, 다른 소스의
타임라인이나 실제 영상 편집점 불일치는 제작을 중단한다. 강의 제작의 사전 검사는
음성만 내보낼 때도 Node.js와 덱 도구 환경을 필요로 한다.

## 구현 단계의 역할 (아래 단계는 도입 계획이 아니라 현재 구성 설명)

### 1단계: 독립 CLI

개발과 벤치마크가 쉬운 명령부터 만든다.

```text
local-tts synthesize
  --model <model-key>
  --voice-profile <profile-key>
  --text-file <utf8-text>
  --output <wav-path>
  --metadata <json-path>
```

### 2단계: 재사용 음성 프로필

참조 음성, 정확한 전사와 모델별 prompt를 하나의 프로필로 묶는다. 원본 음성은
`data/private/voice/`의 불변 정본을 읽기 전용으로 사용하고 해시를 기록한다.

### 3단계: 기존 Node 파이프라인 연동

로컬 엔진 결과를 `deck/tools/course-media.mjs`의 타임라인 계약으로 내보낸다.
자막 생성은 `deck/tools/captions.mjs`, 화면 촬영·영상 결합은
`deck/tools/capture.mjs`로 분리한다. 예전 `narration.mjs captions/capture`
명령은 기존 자동화가 깨지지 않도록 호환 진입점으로만 유지한다.

### 4단계: 로컬 제작 허브

Electron 앱이 강의 소스 경로와 모든 산출물 경로를 로컬 JSON에 저장한다.
임의 텍스트는 2~8개 후보로 생성해 사용자가 직접 선택하고, 강의 영상 제작은
항상 TTS·정렬·브라우저 캐시를 우회한다.

텍스트 후보는 비교를 위해 후보마다 다른 시드를 쓴다. 강의 제작은 고정 시드와
의미 단위 청킹을 사용하므로 캐시를 우회해도 생성 조건은 재현 가능하게 유지한다.

## 대본 시간 제어

강의 대본에서 같은 화면 스텝의 자동 애니메이션과 발화를 맞춰야 할 때는
`[2s]`, `[1.5s]`처럼 단독 줄에 쓴 마커를 사용한다. 엔진은 마커 앞뒤를 별도
음성 조각으로 합성하고 지정한 무음을 삽입하지만, 화면 타임라인과 자막에서는
다시 하나의 스텝과 연속된 원문으로 내보낸다. 마커 자체는 읽거나 자막에 넣지
않는다. 허용 범위는 0.1~10초이며, 일반적인 문장 호흡은 TTS에 맡긴다.

한 줄 전체가 괄호인 제작 지시문은 TTS·자막에서 제외하지만 시간은 만들지
않는다. 실제 대기가 필요하면 괄호 설명 대신 `[Ns]`를 사용한다.

질문 스텝 끝의 `[2s]` 뒤에 같은 페이지의 답변 스텝이 있으면, 다음 스텝의
발화 전에 지정한 무음을 넣는다. 질문과 답변은 다른 음성 청크로 생성하고,
질문의 `forcedPauses`에 답변 시작 시각을 기록한다. 이 대기는 음성 검수·트림
이후 트랙 조립 단계에서 넣는다. 페이지의 마지막 스텝처럼 이어질 발화가 없거나
마커 앞에 문장이 없으면 기존대로 입력 오류로 처리한다.

스텝 첫 줄의 `[1.6s]`처럼 마커 뒤에 읽을 문장이 있으면 발화 전 대기로 허용한다.
다음 청크 앞의 실제 무음으로 삽입하며, 첫 청크라면 오프닝 패드 뒤에 더한다.
마커는 TTS·자막에서 제외하고 단어 시각에는 실제 대기를 반영한다. 마커만 있는
스텝과 문장 없이 연속되는 마커는 계속 입력 오류다.

## 캐시 정책

독립 CLI는 실험 재현성과 부분 재생성을 위해 해시 캐시를 지원한다. 캐시 키에는
최소한 아래 값을 모두 포함한다.

- `ttsText`
- 모델 저장소와 정확한 리비전
- 양자화 방식
- 음성 프로필 해시
- 언어·속도·seed 등 생성 설정
- 엔진 스키마 버전

같은 대본 한 스텝만 바뀌면 그 클립만 다시 생성되어야 한다. 모델이나 음성
프로필이 바뀌면 전체 길이가 달라질 수 있으므로 기존 타임라인은 다시 만든다.

로컬 제작 앱은 `course_pilot --no-cache`와 캡처의 `--no-cache`를 항상 전달한다.
따라서 앱에서 만드는 영상은 기존 음성 클립, 강제 정렬 JSON, Chromium HTTP
캐시를 읽지 않는다.

## 파일 정책

- 모델은 사용자 공용 Hugging Face 캐시에 둔다.
- 벤치마크 출력은 `artifacts/`에 두고 Git에서 제외한다.
- 소스 녹음은 `data/private/voice/`를 읽기 전용으로 사용한다.
- 앱에서는 단일 `outputRoot`만 설정하고 기본값은 프로젝트의 `output/`이다.
- `output/videos`, `output/voices`, `output/tts`, `output/projects`, `output/edits`는
  앱이 자동으로 만들고 관리한다.
- 실제 입력 경로와 `outputRoot`는 `artifacts/app-settings.json`에 저장한다.
- 이전 `artifacts/course-pilots`, `artifacts/voice-candidates`,
  `artifacts/production`, `artifacts/video-edits` 결과는 읽기 호환만 유지한다.

## 결과 검수 상태

앱의 자동 검증과 사용자 청취 승인은 서로 다른 상태다. 자동 검증은 음성·영상
파일, 실제 길이, 타임라인과 자막 범위를 검사한다. 사용자가 결과를 직접 들은 뒤
누르는 `청취 승인`은 같은 산출물 폴더의 `validation-report.json`에 선택 필드로
추가한다.

```json
{
  "review": {
    "status": "approved",
    "updatedAt": "2026-08-27T00:00:00.000Z"
  }
}
```

승인 취소는 `status`를 `pending`으로 바꾼다. 자동 검증 결과는 이 동작으로
변경하지 않는다.

## 자동 발음 검수와 부분 재생성

### 영어 인용문 제작 프로필 (2026-09-09 승인)

한국어는 `jaeho-ko-r16-v1` 0.60과 참조 음성·전사를 유지한다. 영어 인용문은
사용자가 선택한 비교 5번, `english-speaker-only-v1`을 사용한다. English로
따로 생성하며 LoRA 기여를 끄고 참조 전사를 주지 않는다. 본인 음성은 화자 특징
추출에만 사용한다. 미국식 발음은 청취 목표이며 지역 억양을 강제하는 API나
자동 평가 결과로 표현하지 않는다.

`english_voice.py`는 발음 사전의 영어 literal, 따옴표 안의 영어 문장,
영어만 있는 입력을 구분한다. 새 영어 문장(영문 단어 3개 이상)은 발음 사전의
내부 용어 치환에서 보호한다. `Agents-as-Tools` 같은 단일 식별자와 한국어 안의
짧은 미지정 영문 용어를 영어 문장으로 간주하지 않는다. 자막 원문은 유지한다.

한 청크 안에서 언어가 바뀌면 각각 생성·트림하고 120ms 간격으로 조립한다.
영어에는 같은 청크의 한국어 발화 RMS를 기준으로 일정한 게인만 적용한다.
한국어 조각은 변경하지 않는다. 한국어가 없는 입력은 이 상대 음량 보정을
하지 않으며 기존 최종 음량 정규화를 사용한다.

어댑터가 로드된 모델은 영어 생성 iterator가 끝날 때까지 LoRA 모듈의 scale을
0으로 두고 `finally`에서 원래 값을 복원한다. 설치된 LoRALinear의 계산은
`base(x) + scale * delta(x)`다. 두 번째 대형 모델을 메모리에 올리지 않는다.
생성·검수가 끝나면 라우터의 모델 참조도 해제한 뒤 정렬 모델을 로드한다.

정책·분리된 문장·음량 정책·간격은 영어가 든 청크의 캐시 키에만 추가한다.
한국어만 있는 청크의 키와 합성 호출은 유지한다. 음성 메타데이터는 각 언어의
실제 샘플 범위·길이·게인을 `voiceRouting`에 보관한다. 기존 스텝 키·클립 조립·
단어 정렬·export 계약은 유지한다. 새 제작, 페이지 재생성, 텍스트 후보,
독립 prosody 후보 생성이 같은 분리 함수를 사용한다.

Whisper도 이 실제 구간별로 `ko`/`en`을 사용한다. 영어 받아쓰기는 비교 단계의
한글 용어 치환에서 다시 보호하고, 원래 받아쓰기 문자열은 `englishChecks`에
보존한다. 영어 단어 누락·치환은 기존 후보 예산 안에서 재시도한다. 영어만
문제면 앱의 확인 구간도 해당 영어의 실제 시각으로 좁힌다. 한국어의 초당 글자 수
관문은 한국어 구간에서만 계산하며 영어의 초당 단어 수는 참고값으로 기록한다.
이 검사는 미국식 flap T·강세·억양·목소리 유사도를 승인하지 않는다.

#### 한국어 문장 안의 영어 철자 유지

2026-09-09~10 전체 문장 비교에서 Observation을 한글로 치환하지 않고 한국어
모드·참조 음성과 전사·LoRA 0.60으로 읽는 방식이 청취 승인됐다. 사전의
`literal: true, inline: true`는 철자만 보호하며 영어 음성 라우터는 이 항목을
분리 대상으로 사용하지 않는다. 단어 앞뒤 조사·어미와 음색·생성 호출을 그대로
유지한다. 완전한 영어 인용문은 기존 5번 경로로 처리하며 문장 보호를 inline
용어 보호보다 먼저 수행한다. 밑줄·하이픈으로 연결된 다른 식별자의 일부는
선택 용어로 취급하지 않는다.

`comparisonReading`의 한글 표기는 받아쓰기 표기 비교와 발화 속도 계수에만
사용한다. 예를 들어 Observation의 철자 11개를 한국어 11음절로 계산하지 않도록
옵저베이션으로 비교한다. 실제 합성 입력과 자막은 Observation을 유지한다.
기존 누락·발음 거리 임계값은 유지하며 이 비교는 영어 발음·강세 승인과 다르다.
현재 제작 사전의 대상은 Observation, Anthropic, permission denied(붙임·밑줄
별칭 포함), Artificial Analysis, Intelligence Index, Boris Cherny, Y Combinator다.
Authentication/Authorization은 보류, Attention Budget/knowledge cutoff는 불채택이며
기존 한글 읽기를 유지한다. 서비스·지표 전체 명칭은 두 승인 항목이 연속 적용돼도
음성은 하나의 한국어 문장으로 생성된다.

강의 제작의 기본 음성 경로는 다음 폐루프를 사용한다. 판독기는 생성기보다 먼저
올라와 함께 상주하므로, 청크는 만들어진 자리에서 바로 검수된다.

```text
자막 원문
  → 한국어 자연스러움 검사 (고유어/한자어 수량 선택)
  → TTS 전용 발음문·나머지 숫자 정규화
  → 청크 생성 (시드 1개)
  → Whisper large-v3-turbo 독립 받아쓰기·파형 검사
  → 발음 통과 후보의 단어 내부 끊김 검사 (실제 무음 + Whisper 단어 시각)
  → 깨끗하면 종료, 아니면 다음 시드로 되돌아감 (최대 4회)
  → Qwen TTS·Whisper 메모리 해제
  → Qwen ForcedAligner 단어 시각 생성
```

자연스러움 검사는 Whisper보다 먼저 실행한다. Whisper는 `열 개`와 `십 개`를
모두 `10개`로 적을 수 있으므로 전사 결과만으로 둘을 안정적으로 구분할 수 없다.
`korean_naturalness.py`는 문맥이 명확한 `개·명·가지`의 100 미만 수량을 고유어
관형형으로 바꾸고, 100 이상은 기존 한자어 정규화에 맡긴다. 제작에서 이미 승인된
`50개 → 오십 개`는 명시적 예외다. `번·장·시간`처럼 뜻에 따라 읽기가 달라지는
단위는 자동 판단하지 않고 발음 사전의 구체적인 문구로 정한다.

자연스러움 검사가 선택한 값은 manifest의 `naturalness.checks`에 페이지·스텝과
함께 기록한다. 이후 Whisper는 그 최종 발음문을 실제 음성이 따랐는지만 검사한다.

사전의 `literal: true`로 지정한 영어 낭독 구간은 합성 치환뿐 아니라
`requiredPronunciations` 추출에서도 보호한다. 예를 들어 `Do my Bots ...`를
영어로 읽도록 정했으면 그 안의 `Bots → 봇츠`를 별도로 요구하지 않는다.
보호 구간 안의 숫자·모델명도 한글 읽기를 추가하지 않으며, 구간 밖의 용어와
숫자 검사는 유지한다.

모든 청크를 검수하되 재시도는 실제로 어긋난 청크에만 쓴다. 정상 청크가 생성
1회로 끝나므로, 강의 전체를 검수하면서도 이전의 무조건 3회 생성보다 빠르다.

`transcript_coverage.py`의 `ko-clause-omission-v1`은 원문 순서대로 전사를
대조해 연속된 한국어 3단어·10음절 이상의 순수 삭제를 별도 `contentChecks`로
기록한다. 다른 단어로의 치환·띄어쓰기·짧은 발음 차이는 기존 검사를 따른다.
같은 말이 반복되면 먼저 들린 앞쪽 구절을 유지하고 뒤쪽 삭제의 원문 오프셋을
보존한다. Whisper 두 판독 중 관대한 판정을 고르는 규칙은 그대로다.

같은 누락 범위가 두 후보에서 연속되면 다음 후보부터 해당 문장의 기존 마침표·
쉼표 경계에서 입력을 나눠 합성한다. 글자·구두점·원문 자막·청크/스텝 키는
유지하며, 조각 사이 200ms와 실측 길이로 다시 하나의 후보를 만들고 전체를 검수한다.
한 후보의 내부 모델 호출 수는 늘 수 있으나 후보 한도는 기존 4회다. 복구를
시작한 뒤에는 다른 발음 경고가 남아도 원래의 실패한 입력 구조로 돌아가지 않는다.
복구 조각과 정책을 캐시 해시에 포함하고 `recovery`에 입력·실측 시각을 기록한다.
전체 제작 프로필·발음 거리 임계값·정상 청크의 입력과 캐시 해시는 변경하지 않는다.

페이지 후보는 기존의 후보당 1회 정책을 유지한다. 영상에 기록된 반복 누락을
`--recovery-findings`로 전달하고, **현재 전체 발음문과 정확히 같은 경우에만**
첫 후보부터 분할 복구를 사용한다. 대본이 바뀌었으면 과거 페이지 번호나 단어만으로
복구 계획을 재사용하지 않는다. 이 복구의 실제 음성·연결부 청취 승인은 별도다.

비교는 발음 공간에서 한다 (`korean_phonetics.py`). 한글을 자모로 분해하고,
전사에 남은 로마자를 한국어 자모음 이름으로 읽고, 현대 한국어가 구분하지 않는
차이(된소리, `ㅐ/ㅔ`)만 접는다. 거센소리는 접지 않는다 — `런타임 → 런팀` 같은
오독이 살아 있어야 한다. 용어 검사는 부분 문자열이 아니라 근사 부분 일치 거리로
판정하고, 기대 횟수보다 적게 들리면 누락으로 본다.

판정은 통과 / 확인 권장 / 재생성 필요 세 단계다. 실패만
`quality.summary.needsReview`에, 경고는 `quality.summary.listenSuggested`에
챕터·화면 ID·페이지 번호로 기록한다. 1차 판독에서 걸린 청크는 다른 디코딩
온도로 한 번 더 읽고 관대한 쪽을 취해 ASR 노이즈를 배제하며, 경고가 모든
시드에서 재현되면 체계적 오독으로 보고 실패로 승격한다.

`prosody.py`는 별도로 250ms 이상 내부 무음을 찾는다. 발음 검수를 통과한 후보에
이런 무음이 있을 때만 상주 Whisper의 단어 시각을 요청한다. 원문과 정확히 매핑된
한글 단어 안에서 양끝 100ms를 제외한 위치에 무음이 있으면, 기존 Qwen
ForcedAligner로 독립 확인한다. 두 모델이 같은 단어·같은 실제 무음을 내부 끊김으로
판정하면 다른 시드로 재생성한다. 불일치는 아래의 미배정 발화 검사로 확인한다.
기존 발음 판독 설정과 거리 임계치는 유지한다.
Whisper를 다른 온도로 두 번 읽는 방식은 단어 경계 오류도 반복해서 폐기했다.
실제 검증의 `건 / 도구의`에서 Whisper는 앞 단어 끝을 뒤 단어에 붙였지만,
Qwen 정렬은 단어 사이 무음으로 판정했다. 추가 발화 근거도 없는 이런 불일치는
`unconfirmedChecks`에만 남긴다.
Qwen은 단어의 시간 경계만 확인한다. 발음·누락 판독은 계속 독립 Whisper가 담당한다.

v3는 정렬기가 단어의 앞부분이나 뒷부분을 누락한 경우도 검사한다. `똑똑하게`의
실제 끊김 시험에서 Qwen이 무음 앞을 단어 끝으로 잡아, 뒤의 발화를 어떤 단어에도
배정하지 않았다. Whisper가 그 구간을 같은 단어에 배정했고, 인접 Qwen 단어와
100ms 이상 떨어진 미배정 구간에 주기성 있는 발화가 80ms 이상 있으면 끊김 근거로
채택한다. 앞뒤 어느 쪽 누락에도 적용하며 무음·잡음·짧은 신호는 이 근거가 될 수 없다.
이는 음높이 평가나 음성 보정이 아니라, 실제 소리가 남아 있는지 확인하는 CPU 검사다.

띄어쓰기 차이만으로는 재생성하지 않는다. 문장부호·공백·명시적 `[Ns]` 경계와
짧은 파열음 폐쇄 구간은 보호한다. 불명확한 전사 매핑, 낮은 확신도, 잘못된 시각,
판독 창 경계는 자동 판단에서 제외하며 검사 범위는 후보의 `prosody.status`에 남긴다.
이 검사는 억양·감정·음색·영어 원어민 발음·모든 음절 늘임을 평가하는 지표가 아니다.

후보 선택은 발음 정확도를 우선하고 그다음 끊김 경고 수와 길이를 비교한다.
재시도 한도는 기존 최대 4회를 공유한다. 끊김 경고는 모든 시드에서 반복돼도
오독 실패로 승격하지 않는다. 자동으로 해결되지 않은 끊김만 `listenSuggested`에
남기며, 앱은 해당 단어의 실제 영상 시각과 용어를 표시한다.

새 모델이나 음성 필터는 추가하지 않는다. 시각 판독에 따른 추가 시간은
`qualityEvaluationMs`, 실제 프로세스 최대 Metal 메모리는 기존 항목에 포함된다.

Metal 메모리는 TTS 약 11.6GB + Whisper 약 1.6GB가 함께 상주한다. 끊김 의심
후보에서만 Qwen 정렬기를 잠깐 로드해 확인하고 해제한다. 최종 자막용 전체 정렬은
기존처럼 TTS·Whisper를 해제한 뒤 수행한다. 실제 최대치는 manifest의
`performance.peakProcessMetalMemoryGb`에 남는다.

음성 판정은 제작 성패를 가르지 않는다. 파일·영상 검증만 제작 실패가 되고, 음성
의심 구간은 완료 패널과 최근 결과에 시간대·페이지·사유로 실린다.
완료 안내는 파일 검사와 음성 판정을 분리하며 챕터 제작에서도 모든 레슨의
미해결 항목과 각 영상의 열기 대상을 합산한다. `재생성 필요`를 `모두 통과`로
표시하지 않는다. 검수 행은 구절 누락과 생성 횟수를 바로 보여 주고 삭제 범위
전체를 강조한다. 누락된 단어의 0ms 강제 정렬값을 발화 증거로 쓰지 않으며,
해당 문장 문맥으로 이동한다. 다른 반복 단어의 어느 출현인지 불명확하면 청크
범위를 유지한다. 과거 보고서도 저장된 전사로 표시를 복구하며 기록·확인 키는
덮어쓰지 않는다.

페이지 타임라인이 있는 영상의 음성 재생성은 전체 오디오 트랙을 교체하지 않는다.
선택 페이지 앞·교체 구간·뒤를 분리하고 교체 구간만 새 길이에 맞춘 뒤 다시
잇는다. 이후 타임라인도 길이 차이만큼 이동해 다음 부분 수정이 가능하게 유지한다.

## 짧은 발화 재시작 검사

`restarts.py`의 `ko-acoustic-restart-v1`은 받아쓰기에 남지 않은 짧고 약한
첫 발화 뒤의 재시작을 별도 청취 경고로 검사한다. 60~220ms 첫 발화,
70~240ms 쉼, 뒤 발화의 비슷한 주파수 변화(정규화 유사도 0.72 이상)와
두 배 이상 강한 프레임 RMS가 함께 있어야 후보가 된다. CPU에서 계산하며
새 모델·음성 필터·패키지를 추가하지 않는다.

후보가 있으면 기존 Qwen 독립 정렬을 재사용해 두 소리가 같은 한국어 원문
단어 안에 있고, 첫 발화가 단어 시작 100ms 이내인지 확인한다. 원문에 있는
반복, 첫 두 음절의 초성이나 모음이 같은 말, 단어 사이 경계는 제외한다.
이는 보수적인 약한 시작음 재시작 탐지이며, 크기가 비슷한 반복이나 쉼 없는
반복, 모든 말더듬을 검출한다고 약속하지 않는다. 유사도는 오독 확률이 아니다.

발음 검수를 통과한 후보에 적용하고, 경고가 있으면 기존 최대 4회 예산 안에서
다른 시드로 재생성한다. 끝까지 남으면 `짧은 발음 반복 확인 필요`와 해당 단어의
실제 영상 시각을 표시한다. 반복 경고만으로 제작 실패나 명백한 오독 판정으로
승격하지 않으며 파형을 자동 절단하지 않는다. 독립 정렬이 없으면
`alignment-unavailable`로 기록한다. 제작 음성 0.60과 기존 관문은 유지한다.

## 사람이 직접 검수하고 수정하는 화면

`영상 검수·수정`은 완성 영상의 플레이어, 페이지 대본·탐색, 자동 확인 권장,
직접 선택을 한 화면에 모은다. 완료 화면과 최근 결과는 이 화면으로 연결한다.
기존 `영상 편집`은 합치기와 자르기만 제공한다. 자동 권장 항목을 누르면 해당
시각과 페이지가 선택되며, 목록에 없는 문제도 현재 재생 페이지에서 수정한다.

페이지 재생성 후보는 같은 화면에서 원본과 비교하고 직접 하나를 선택해 새
버전으로 저장한다. 생성 요청의 영상 토큰과 페이지·길이 정책을 후보에 고정해
후보 생성 후 다른 페이지를 선택해도 적용 대상이 바뀌지 않는다. 다른 영상을
열면 이전 후보 적용 대상은 지운다. 수정본을 열어 같은 위치부터 검수를 이어간다.
기존 길이 유지에서 새 음성이 더 길면 끝을 자르지 않고 적용을 거절하며,
새 음성 길이에 화면 맞춤을 선택하도록 안내한다.

짧은 불필요한 소리는 0.05~2초를 지정해 `mute-region`으로 무음 처리한다.
양 끝 5ms 게인 전환을 적용하고 영상 스트림은 복사하며 자막·타임라인 시각을
유지한다. 원본은 보관하고 새 출력 이름으로 저장한다. AAC 패킷에 따라 컨테이너
길이는 한 오디오 프레임 정도 차이날 수 있다. 영상 타임라인이 없는 파일에는
페이지 재생성을 제공하지 않는다. 수동 수정 결과는 청취 승인 전 상태다.

`구간 음성 교체`(`replace-region`)는 0.05~120초의 선택 구간과 120초 이하의
준비된 음성 파일을 사용한다. 새 UI 기본값 `match-audio`는 음성을 자르거나
속도를 바꾸지 않고 선택 구간의 화면을 같은 비율로 늘이거나 줄인다. 뒤의
화면·타임라인·자막 시각은 길이 차이만큼 이동하며 새 파일로 저장한다. 이는
새 단어 정렬을 추론하는 기능이 아니며 타임라인에 `proportional-region-retime`을
기록한다. 기존 자막의 문구를 유지하므로 원문과 같은 말을 준비해야 한다.
`keep-video`는 기존 동작처럼 짧으면 무음을 채우고 길면 적용을 거절한다.
음성 양끝 5ms 페이드를 유지하고 두 길이 정책 모두 저장 전에 차이를 표시한다.

다듬기 구간 선택은 `4:55.120`·`295.120`·`1:04:55.120`을 받고 미완성 입력은
0초로 취급하지 않는다. 0.01초 버튼·방향키(Shift 0.1초), 현재 재생 위치 표시,
파형의 시작/끝 손잡이, 확대/축소/선택 범위 맞춤을 제공한다. 구간 탭은 현재
듣는 위치에서 시작하고 자동 확인 항목은 해당 문장 문맥을 채워 준다.
영상 밖·역전·최소/최대 길이·긴 교체 파일 오류를 저장 전에 표시한다.

`review-media.mjs`의 파형은 선택한 로컬 영상 토큰으로 최대 120초만 읽어
1,800개 이하의 진폭 값으로 반환한다. 요청을 직렬화하며 오래된 선택은 폐기한다.
구간 듣기와 수정 후 미리듣기는 FFmpeg로 실제 WAV를 잘라 임시 파일에서 재생한다.
`timeupdate`의 지연에 따라 50ms 구간이 수백 ms 더 재생되는 문제를 피한다.
미리듣기는 검수 배속을 따르며 범위·영상·파일·길이 정책을 바꾸면 무효화한다.
임시 파일은 최근 8개만 유지하고 앱 종료 때 정리한다.

수정 구간에 겹친 옛 ASR 판정을 새 음성의 증거로 재사용하지 않고 `교체 후
청취 확인`/`무음 처리 후 청취 확인`으로 바꾼다. 다른 구간의 판정과 사용자 확인
상태는 새 시각에 맞춰 보존한다. 새 결과의 전체 청취 승인은 pending이다.
다른 영상으로 전환하면 교체 파일·범위·미리듣기 상태를 초기화한다.

## 승인한 영어 정책을 기존 영상에 적용

`scripts/retrofit_course_english.py`는 기존 타임라인의 원문에서 승인된 inline
용어를 찾고, 그 용어가 들어간 완전한 문장만 교체한다. 원래 발음문에서 해당
음차만 영어 철자로 바꾸므로 다른 숫자·약어·문구는 당시 제작 상태를 유지한다.
기본 4후보의 내용·발음·운율 검사를 적용하며, 사용자 요청으로 다시 만든 비교는
별도 승인 기록을 남긴다. 새 생성물의 reviewStatus를 자동으로 approved로
바꾸지 않는다. 자동 검사 통과와 개별 음성의 청취 승인을 구분한다.

연속 편집은 원본 manifest의 음성으로 돌아가지 않는다. ready의 sourceAudioPath와
sourceAudioSha256으로 최신 편집 PCM을 지정하고, 최신 타임라인과 자막을 기준으로
수정 밖 샘플을 보존한다. 파일명이 바뀌었을 때는 유일한 해당 폴더 영상과 편집
음성의 일치를 확인한 뒤 별도 입력 스냅샷에 경로를 기록한다. 기존 보고서는 수정하지
않는다. 과거 검수·편집 이력은 sourceValidation과 previousEditTiming에 보존한다.

전체 단어 정렬이 특정 단어에 0ms를 주면, 앞뒤 유효 단어를 포함하는 실제 음성
구간을 다시 독립 정렬한다. 실제 재정렬도 유효하지 않으면 렌더 준비를 중단하며
비율로 단어 시간을 만들어 채우지 않는다. 준비 음성과 최종 AAC의 일치, 교체 밖
PCM, 자막 묶음과 원본 파일 해시를 확인하고 연결부 청취 항목은 별도로 남긴다.
