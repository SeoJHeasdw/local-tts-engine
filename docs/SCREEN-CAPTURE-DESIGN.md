# 화면 녹화 설계 근거

2026-09-18 사용자 인터뷰로 정하고 같은 날 구현했다. 현재 구조는
[ARCHITECTURE](ARCHITECTURE.md#화면-녹화), 규격과 측정은
[VIDEO-QUALITY](VIDEO-QUALITY.md#화면-녹화), 상태는 [HANDOFF](HANDOFF.md)에 있다.
이 문서는 왜 그렇게 정했는지만 남긴다.

## 목적

**IBM BoB Level 3 인증 제출 영상**(10~15분) = HTML 강의 덱 화면 + IBM Bob 실제 조작 화면.
덱 촬영은 이미 됐고 빠진 것은 Bob 조작 화면 녹화였다. 제품이 아니라 사용자 본인의
편의 도구이므로 필요한 만큼만 만든다.

## 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 찍는 범위 | 디스플레이 하나 전체 | 창·영역 선택 없이도 Bob 화면을 한 모니터에 두면 된다 |
| 화질 | 소스 해상도 그대로 | 확대·축소는 화질을 잃고, 1080p 모니터면 덱 1080p와 복사로 합쳐진다 |
| 녹화 방식 | 수동 시작·정지, 취소는 폐기 | 조작 시연은 타임라인이 없다 |
| 내레이션 | 편집에서 붙인다 | 기존 구간 음성 교체·합치기를 그대로 쓴다 |
| 소리 | "음성 포함" 토글, 기본 끔, 기억하지 않음 | 화면 속 소리까지 녹음할 일은 90% 넘게 없다 |
| 결과 위치 | `output/edits/<날짜>/<이름>/`, `record-display` | 결과 목록·이름 변경·다듬기를 고치지 않고 쓴다 |
| 메뉴 | "새 영상" 다음 "화면 녹화" | |

만들지 않는 것: 창·영역 선택, 타임라인 자동 녹화, 큐 화면, 시스템 소리용 루프백 장치
설치 자동화, 네이티브 코드. 루프백 장치(예: BlackHole)는 필요해질 때 라이선스와 함께
사용자와 정하고, 앱은 목록에 있는 장치만 보여 준다.

## 설계 전제가 된 실측

- **정지는 stdin `q`.** SIGINT로도 파일은 남지만 종료 코드가 255라 실패와 구별되지 않는다.
  stdin을 터미널에서 물려받은 ffmpeg는 SIGTTIN으로 멈추고 SIGKILL만 먹혔다.
- **정지는 취소와 다른 경로.** 기존 중지는 결과를 버리고 3초 뒤 SIGKILL한다. 정지는
  정상 완료이므로 작업자에게만 SIGUSR1을 보내고 강제 종료 시계를 두지 않는다.
- **무음 트랙은 사후에.** 편집이 음성 없는 영상을 거절한다. 녹화와 동시에 무음을 만들면
  영상 8.08초에 음성 5.35초에서 끊겼다.
- **권한 판정은 실제 촬영으로.** 앱은 `./app.sh`로 떠서 ffmpeg의 책임 프로세스가 실행한
  터미널 앱이다. Electron의 권한 조회는 이 차이를 모르므로 한 프레임 촬영의 성패로 본다.
  권한이 없을 때 오류인지 검은 프레임인지는 권한을 회수해 보지 않아 미확인이다.
- **음성 포함은 쓰지 않는다(2026-09-21 결정).** 구현 뒤 실측에서 ffmpeg가 마이크 소리의 약
  13%를 놓쳤다. 수치는 VIDEO-QUALITY, 결정은 DECISIONS에 있다. 토글은 기본 끔으로 남아 있다.
