# 제품화 판단과 실행 계획

> 점검일: 2026-09-03
> 결론: 유료 비공개 베타의 기반은 있으나, 일반 고객에게 설치 파일로 판매할
> 단계는 아직 아니다.

## 한 줄 제품 정의

Apple Silicon Mac에서 **내 목소리로 대본을 읽고, 자막과 영상을 로컬에서
완성하는 한국어 크리에이터 스튜디오**다.

첫 제품은 서버형 SaaS가 아니라 로컬 데스크톱 앱으로 잡는다. 개인 음성과 원본
영상이 기기 밖으로 나가지 않고, 생성량에 따라 TTS 요금이 늘지 않는 현재 장점을
그대로 상품 가치로 쓸 수 있기 때문이다. 서버 계정은 나중에 라이선스, 업데이트,
결제만 담당하고 음성 생성은 로컬에서 계속 실행하는 구성이 적합하다.

`유튜브 자동화`라는 표현만 앞세우지는 않는다. 현재 앱이 잘하는 것은 저품질 영상을
대량 업로드하는 자동화가 아니라, 창작자가 쓴 대본을 자신의 목소리와 검수 과정을
거쳐 반복 제작하는 일이다.

## 현재 팔 수 있는 가치

| 기능 | 현재 상태 | 고객 가치 |
| --- | --- | --- |
| 텍스트 → 개인 음성 후보 | 동작·검수 완료 | 대본 수정과 재녹음 시간을 줄임 |
| 음성 후보 직접 선택 | 동작 | 생성 결과를 사람이 최종 통제 |
| 기존 영상 합치기·자르기·음성 교체 | 동작 | 별도 편집기 왕복을 줄임 |
| 강의 대본 → 자막·영상 | 현재 전용 강의 형식에서 동작 | 반복 강의 제작 자동화 |
| 로컬 처리 | 동작 | 음성 데이터 비공개, 사용량 과금 없음 |
| 자동 파일 검증 + 사람 확인 | 동작 | 대량 생성의 조용한 실패를 줄임 |

이 중 첫 유료 베타의 범위는 `텍스트 목소리 + 기존 영상 음성 교체`가 가장 안전하다.
강의 영상 자동 제작은 아직 `udemy-agent`의 대본·슬라이드 계약에 의존하므로 일반
유튜브 사용자의 입력 형식으로 바로 판매하면 안 된다.

## 2026-09-03에 반영한 기반 개선

- 앱에 박혀 있던 사용자 홈 절대 경로를 제거하고, 형제 프로젝트 또는 명시적
  설정으로 강의 소스를 찾게 했다.
- Homebrew의 고정 경로 대신 현재 `PATH`, Apple Silicon 기본 위치와 명시적
  재정의를 차례로 확인해 Node.js, FFmpeg와 FFprobe를 찾게 했다.
- 텍스트 목소리 생성의 준비 조건에서 강의 전용 저장소를 분리했다. 고객은 강의
  소스가 없어도 참조 음성과 전사문만으로 이 기능을 사용할 수 있다.
- 텍스트 음성, 기존 영상 편집, 강의 영상 제작의 준비 상태를 따로 계산한다.
- `npm run doctor`로 개인 경로를 기본 출력하지 않는 설치 진단을 제공한다.
- `npm test` 하나로 Electron과 Python 테스트를 함께 실행한다.

이 변경은 기존 제작 프로필 `jaeho-ko-r16-v1`과 강도 `0.60`, 강의 생성 조건,
출력 폴더와 검수 흐름을 바꾸지 않는다.

## 판매 전에 반드시 해결할 항목

### P0 — 유료 비공개 베타 전

1. **고객용 음성 온보딩**
   - 참조 음성 녹음 안내, 정확한 전사 입력, 30초 샘플 검수 흐름을 앱 안에 만든다.
   - 본인 음성 또는 명시적 사용 허가를 받은 음성이라는 확인 기록을 음성 프로필에
     저장한다.
   - 개인 제작 어댑터와 학습 데이터는 고객 빌드에 포함하지 않는다.

2. **고객 입력 계약**
   - 일반 텍스트·SRT·CSV 중 하나를 첫 공개 입력 형식으로 정한다.
   - 영상은 고객이 가진 MP4를 넣고 음성 교체부터 지원한다.
   - 슬라이드 자동 생성과 유튜브 업로드는 첫 버전에서 분리한다.

3. **설치 패키지**
   - Python 런타임, 앱 코드, 필요한 실행 도구의 설치 방식을 확정한다.
   - 모델은 첫 실행 때 예상 다운로드 용량과 목적을 알린 뒤 받는다.
   - Developer ID 서명, hardened runtime, 공증과 스테이플링을 자동화한다.

4. **오픈소스·코덱 검토**
   - Qwen3-TTS Base는 현재 Apache-2.0, MLX-Audio는 MIT로 확인됐다.
   - FFmpeg는 빌드 옵션에 따라 LGPL 또는 GPL이 적용된다. 현재 로컬 바이너리는
     `--enable-gpl --enable-libx264` 구성이고 영상 명령도 `libx264`를 사용한다.
     이 바이너리는 고객 앱에 그대로 묶지 않는다. 배포 방식과 코덱 경로를 별도로
     확정해야 한다.
   - 모든 Python/NPM 전이 의존성의 SBOM과 제3자 고지를 만든다.

5. **장애 복구와 지원**
   - 앱 종료 후 미완료 작업을 감지하고 `실패/중단`으로 복구한다.
   - 경로를 가린 진단 보고서를 고객이 내보낼 수 있게 한다.
   - 자동 업데이트, 이전 버전 복귀, 릴리스별 마이그레이션 테스트를 만든다.

### P1 — 공개 유료 베타 전

- 하나의 결과 폴더가 아니라 여러 프로젝트를 만들고 전환하는 프로젝트 모델
- 음성 프로필 여러 개, 프로필별 동의·출처·삭제 상태
- 대본 변경분만 다시 만드는 작업 큐와 재시도 내역
- 자막 편집과 발음 사전 UI
- 고객용 튜토리얼 프로젝트와 5분 이내 첫 결과
- 개인정보 처리방침, 이용약관, 환불·지원 정책
- 크래시 리포트와 사용 통계는 기본 비활성 또는 명시적 동의 방식

### P2 — 제품 적합성 확인 뒤

- 유튜브 업로드·예약 발행 연동
- 템플릿 기반 화면 생성 또는 Canva 등 외부 편집 도구 연동
- Windows/NVIDIA 작업자 또는 서버 GPU 작업자
- 팀 공유와 승인 워크플로
- 사용량 기반 서버 처리

## 권장 제품 구조

```text
데스크톱 앱
├── 프로젝트·음성 프로필·동의 기록
├── 대본/SRT/영상 가져오기
├── 로컬 작업 큐와 복구
├── TTS 작업자 (Qwen3-TTS + MLX)
├── 자막·영상 작업자
└── 결과 검수·내보내기

선택적 계정 서버
├── 라이선스와 결제
├── 앱 업데이트
└── 고객 지원 권한
```

개인 음성 원본, 음성 임베딩·어댑터, 대본과 결과물은 기본적으로 로컬에 둔다.
서버형 생성이 필요해질 때만 별도 동의, 전송 암호화, 고객별 저장소, 삭제 기한,
작업자 격리와 감사 로그를 갖춘 새 경로로 설계한다. 현재 로컬 코드를 단순히 HTTP로
감싸 인터넷에 노출하는 방식은 사용하지 않는다.

## 유튜브 고객에게 반드시 알려야 할 점

- 본인 음성을 복제해 보이스오버에 쓰는 것은 YouTube의 현재 공개 예시에서
  별도 AI 공개가 필요 없는 항목으로 제시된다. 다만 타인의 실제 목소리로 그 사람이
  하지 않은 말을 하게 만드는 콘텐츠는 공개 또는 권리 문제가 생길 수 있다.
- AI 사용 공개 자체가 수익화를 막는다고 안내하면 안 된다.
- 반대로 템플릿을 반복한 대량·저가치 콘텐츠는 AI 여부와 무관하게 수익화에서
  불리할 수 있다. 제품 메시지는 `더 많이 업로드`보다 `내 관점이 담긴 콘텐츠를
  더 빠르게 완성`에 둔다.
- 공개 라벨은 타인의 목소리 사용 허가를 대신하지 않는다.

## 현실적인 출시 순서

1. **내부판 유지** — 지금처럼 실제 강의를 계속 만들어 회귀 오류를 잡는다.
2. **관찰형 테스트 3명** — 설치를 직접 지켜보고, 도움 없이 첫 음성을 만들기까지의
   막힘을 기록한다. 무료 또는 비용 보전 수준으로 진행한다.
3. **유료 비공개 베타 10명** — 기능 범위를 텍스트 음성과 기존 영상 음성 교체로
   명시하고, 직접 지원 가능한 인원만 받는다.
4. **공개 베타 판단** — 10명 중 7명 이상이 1주 안에 실제 영상 하나를 완성하고,
   치명적 오류 없이 3회 이상 재사용할 때 패키징·결제에 투자한다.
5. **자동 업로드 검토** — 제작 품질과 재사용이 확인된 뒤에만 YouTube 계정 연동을
   추가한다.
