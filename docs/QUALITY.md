# 음성 검수 계약과 측정 근거

영상 화질·촬영·편집 검수는 [VIDEO-QUALITY](VIDEO-QUALITY.md)를 따른다.

## 제작 기본값

한국어는 Qwen3-TTS 1.7B Base BF16 + `jaeho-ko-r16-v1` 0.60과 짧은 참조 음성·
정확한 전사를 사용한다. 0.60은 과한 학습 흔적과 사람 발화 노이즈를 줄인 사용자
승인값이다. 모델·음성 제작 기본값은 직접 들은 승인을 받아 변경한다.
제작 도중 미등록 용어의 발음 승인을 요구하지 않는다. 합성을 마친 뒤 기존 검수·
확인 완료·페이지 재생성 화면에서 읽기를 확인한다(2026-09-11 사용자 결정).

영어 인용문은 English·LoRA 미적용·화자 특징 참조(`english-speaker-only-v1`)다.
참조 전사를 생략한다. 영어 생성 iterator가 끝날 때까지 어댑터 기여를 0으로 두고
finally에서 원래 값을 복원한다. 두 번째 대형 생성 모델을 올리지 않는다.

사전의 `literal: true, inline: true`는 승인한 영어 철자를 한국어 문장 안에서
보호한다. 단어·조사를 별도 영어 클립으로 나누지 않는다. 일반 영어 인용문은
문장 전체를 보호해 내부 사전 치환을 막은 뒤 따로 생성한다. 언어 경계에는 120ms를
두고 실제 한국어 RMS를 기준으로 영어에 일정한 게인만 적용한다. 각 언어의 실제
샘플 범위·길이·게인은 `voiceRouting`에 남긴다. 영어 구간이 없었던 후보는 그 자리를
`null`로 남긴다 — 기록이 없는 것과 영어가 없던 것은 다른 이야기다. 한국어만 있는
캐시 키는 유지한다.

문장 안 영어 철자 방식은 Observation, Anthropic, permission denied(별칭 포함),
Artificial Analysis, Intelligence Index, Boris Cherny, Y Combinator, RICE에 채택됐다.
RICE는 제품 이름만 잡도록 `caseSensitive`를 켠 유일한 항목이다.

사전의 `to`는 **모델이 실제로 읽는 철자**다. inline 항목은 영어 음성으로 보내지 않고
(`speech_segments`가 건너뛴다) 한국어 모델이 그 철자를 직접 읽으므로, 어떻게 읽히는지는
경험으로만 안다. `RICE`는 대문자 약어라 철자로 읽혔다(2026-09-20 3회 모두 불일치:
"알라이 씨", "RIC", "Rih"). 같은 문장에서 `Rice`·`rice`는 3회 모두 `라이스`였다. 그래서
자막 원문은 `RICE`로 두고 발음문만 `Rice`로 보낸다. 대문자 약어를 새로 넣을 때는
`scripts/probe_term_pronunciation.py`로 재고 넣는다.
승인된 원문 `RICE`에서 바뀐 `Rice`는 미등록 용어로 다시 올리지 않는다. 원문부터
`Rice`였던 표기는 제품명 규칙의 대상이 아니므로 여전히 별도 확인 대상으로 둔다.
Authentication/Authorization은 보류, Attention Budget/knowledge cutoff는 불채택으로
기존 한글 읽기를 유지한다. 단어별 영어 전환은 거절됐다. [청취 근거](DECISIONS.md)를 따른다.

## 생성 전 검사

각 레슨의 대본을 읽고 발음문을 만들 때 미등록 용어·식별자를 기록한다.
이 경고는 제작을 막지 않고 완성 후 검수 목록에 연결한다. 대본 누락·잘못된 범위 등
실제 입력 오류는 기존 입력 준비·대본 처리 단계에서 중단한다.

자막 원문과 발음문을 분리한다. 덱·로컬 사전의 같은 키는 로컬 항목이 우선하며
긴 항목부터 적용한다. 영숫자 하이픈 식별자의 일부만 치환하지 않는다.
보호된 영어 문장 안의 숫자·용어는 한글 읽기를 추가하지 않는다.

`korean_naturalness`는 명확한 1~99개·명·가지를 고유어 관형형으로 바꾼다.
사용자 승인 예외 `50개 → 오십 개`를 유지한다. 번·장·시간은 문맥 없이 결정하지
않는다. 사전 이후 남은 숫자는 한자어로 정규화하고, 남은 영문·식별자는 생성 전
기록한다. 미지정 복합 식별자를 임의의 숫자 읽기로 바꾸지 않는다.
명시적으로 등록한 읽기는 제작 사전을 따른다. 다른 식별자를 개별 하드코딩하거나
자동 등록하지 않는다. 미등록 정보는 실제 청크 시각과 연결해 `voiceFindings`에
남기며, 자동 판독이 통과해도 청취 확인 대상으로 표시한다.

숫자 단위는 낱말 경계를 확인한다(`2시점`은 `두 시점`이 아니다). 사전에서 이미 정한
식별자 읽기에 부분 숫자의 다른 읽기를 중복 요구하지 않는다. 미등록 복합 식별자는
소수점·단위 정규화 중에도 전체 철자를 보존한다. 코드의 밑줄도 보존하며, 과거 밑줄을
제거한 사전 키와 정확히 같은 철자는 기존 등록 읽기를 재사용한다.
받아쓰기가 승인된 식별자의 하이픈만 생략한 경우(`A-2041 → A2041`)에는 **비교에서만**
같은 식별자로 복원한다. 전체 영숫자열이 정확히 같고 다른 등록 항목과 충돌하지 않아야
하며, 다른 번호·문자·빠진 숫자를 허용하지 않는다. 합성 입력의 미등록 철자는 그대로다.

## 생성과 독립 판독

청크마다 생성 → Whisper large-v3-turbo 판독 → 깨끗하면 종료, 아니면 다음 시드로
최대 4회 시도한다(첫 생성 포함 4후보). 후보 N개를 직접 비교하는 페이지 재생성은 후보당 1회 정책이다.
강의 후보가 빈 오디오·완전 무음·비유한 샘플을 내면 그 시도만 실패로 기록하고 같은
4회 한도에서 다음 시드를 쓴다. 입력 오류와 사용자 중지는 재시도하지 않는다. 전부
생성에 실패하면 `quality-failure.json`에 시도별 근거를 남기고 해당 레슨을 실패로 처리한다.
시드를 바꿔도 같게 읽히는 자리는 사용자가 읽을 말을 직접 적어 후보를 만든다. 이는
그 페이지의 발음문을 사람이 정하는 것이며 자막 원문·대본과 사전은 바꾸지 않는다.
대조할 원문이 없으므로 자동 판독을 돌리지 않고 청취 선택으로만 채택한다.
파일 생성 실패와 음성 경고는 별개이며, 남은 경고는 사람이 확인할 수 있게 표시한다.
`--no-auto-quality`로 내용 검수를 끈 직접 CLI 실행에서는 빈 음성·무음 같은
후보 결함만 같은 시도 한도에서 재시도한다. 제작이 끝나도 내용 검수는 `not-checked`로
남기며, 자동 통과 또는 청취 승인으로 표시하지 않는다.

Whisper의 긴 음성 판독은 내부 무음 경계로 나눠 30초 창의 뒤쪽 누락을 피한다.
영어·한국어는 생성 시 기록한 실제 구간별로 각 언어를 판독한다. 영어 단어
누락·치환도 재시도 근거다. 원어민 억양·강세·음색은 이 검사의 보증 범위가 아니다.

비교는 `korean_phonetics`의 자모 공간에서 수행한다. 로마자 잔여 표기, 숫자와
모델명을 정규화하고 된소리·ㅐ/ㅔ는 접되 거센소리와 연음은 임의로 접지 않는다.
1차 판독에서 의심된 청크는 다른 디코딩 온도로 한 번 더 읽어 관대한 판정을 취한다.
각 후보의 `transcriptReview`에 실제 수행한 두 판독과 채택 번호를 보존한다. 경고가
사라진 판독도 남기므로 검수기가 무엇을 놓쳤거나 다르게 해석했는지 재검할 수 있다.

영어는 축약형의 apostrophe를 보존한다(`we'll`과 `well`은 다르다). 누락·치환·삽입을
단어 위치와 함께 `englishChecks.wordEdits`에 기록하며, 영어 뒤에 추가된 다른 언어도
지우지 않고 비교한다. 영어 인용문 주변의 문장부호만 따로 한국어로 합성하지 않는다.

선언한 `comparisonReading`이 있는 영어 용어는 거리만으로 통과시키지 않고 선언
표기와 정확히 맞아야 한다. 허용할 ASR 표기는 사용자 청취 후 `comparisonVariants`에
넣는다. 반복 용어는 허용 표기들을 합쳐 세며 들린 표기는 `heardReading`에 남긴다.
선언 없는 한국어 음차의 기존 거리 관문은 유지한다.

## 누락과 운율

`transcript_coverage`는 순서를 보존하며 한국어 3단어·10음절 이상의 순수 삭제를
기록한다. 같은 구절이 두 후보에서 반복 누락되면 남은 후보부터 기존 문장부호
경계로 나누어 합성·조립·전체 검수한다. 영어 인용문 내부는 분할하지 않는다.
현재 발음문이 과거 기록과 정확히 일치할 때만 페이지 후보의 누락 복구를 재사용한다.
복구 정책·조각은 캐시 해시에 포함하며 원문·청크 키와 최대 후보 수는 유지한다.

긴 문장 속에 묻히는 인접 한국어 낱말·구절 반복과, 앞뒤 낱말이 일치하는 독립 부정어
`안·못` 삭제도 재시도 경고로 잡는다. 원문 반복·띄어쓰기 차이·낱말 일부는 이 관문으로
판정하지 않는다. 같은 경고가 여러 후보에 남았는지는 경고 문구뿐 아니라 실제
낱말·원문 위치로 확인한다. 후보마다 다른 단어를 틀린 경우를 동일 오독의 반복으로
승격하지 않는다. NaN·Infinity 등 유효하지 않은 오디오 샘플은 통과시키지 않는다.

발음을 통과한 후보의 250ms 이상 내부 무음은 Whisper 단어 시각과 Qwen 독립
정렬로 확인한다. 단어 양끝 100ms, 문장·명시적 대기 경계는 보호한다. 정렬이 앞뒤
발화를 놓친 경우에는 인접 단어와 떨어진 미배정 구간의 주기성 발화도 근거로 쓴다.
띄어쓰기·잡음·낮은 확신도·잘못된 시각만으로 재생성하지 않는다.

`restarts`는 60~220ms의 약한 시작음, 70~240ms 쉼, 뒤 발화의 유사도와 두 배 이상
음량을 함께 보고 원문의 같은 단어 안인지 독립 정렬로 확인한다. 원문 반복이나
비슷한 첫 두 음절은 제외한다. 모든 말더듬을 검출하거나 파형을 자동 절단하지 않는다.

발음 정확도를 먼저, 그다음 운율 경고 수와 길이를 비교한다. 운율 경고만으로
오독 실패로 승격하지 않는다. 확인되지 않은 정렬은 근거 부족 상태로 기록한다.
한국어 발화 속도 관문은 한국어 구간에서만 적용하며 영어 속도는 참고 기록이다.

## 자막·화면 정렬 검수

음성의 발음·내용 검수와 자막·화면의 시각 검수는 별개다. 새 강의 제작은 최종 WAV의
말·쉼 경계를 기준으로 단어 정렬을 교정하고, 교정된 `speechStartMs`·`speechEndMs`로
화면 전환과 자막 시각을 계산한다. 완성 음성 재정렬도 같은 교정을 사용한다.
음성·정렬 모델과 기존 `language="English"` 호출 설정은 바꾸지 않는다.

신뢰할 수 있는 기존 단어 시각을 기준점으로 두고, 기준점 사이의 망가진 단어 묶음만
음절 수 가중치로 재배치한다. 기준점은 말 구간 안에 있고 음절에 비해 너무 짧지도(뭉개짐)
너무 길지도(쉼·이웃 음절을 삼킴) 않으며, 음절 비례 위치에서 0.35초 넘게 벗어나지 않은
(모델이 구절 전체를 늦게 잡은 것이 아닌) 단어다. 원래 시각과 보간 범위를 별도로 남긴다. 이는 파형 제약을 이용한 시각 추정이며 실제 단어를 새로 강제 인식한
결과가 아니다. 파형만으로 어느 말을 했는지 확정하거나 보간을 청취 승인으로 표시하지 않는다.

정렬 관문은 스텝의 정렬 끝과 파형 말 끝의 차이, 목소리 위의 화면 전환,
말보다 먼저 끝난 자막, 지나치게 짧은 단어와 자막 누락을 기록한다. 자막은 모든 cue를 본다: cue의 글을 대본 토큰
순서로 스텝에 붙이고 그 글을 읽는 정렬 단어와 비교해, 제 말보다 먼저 사라짐 · 앞 cue의 말이 끝나기 전에 뜸 ·
말보다 늦게 뜸을 0.1초 허용으로 기록한다(`captionText`). 스텝의 마지막 cue만 보는 파형 검사는 그대로 두며,
이 검사는 단어 시각을 믿으므로 보간된 단어의 불확실성을 그대로 따른다. 말 끝 차이는
0.25초, 전환·자막 경계는 0.02초 허용 범위로 검사하며 짧은 실제 한 음절과
연속해서 뭉개진 단어를 구분해 남긴다. 생성 직후에는 자막 검사가 아직 수행되지
않았음을 표시하고, 자막 파일 생성 뒤 다시 검사한다. 미검사·검사 실패·남은 교정
의심점도 경고로 알리며, 정렬 경고 때문에 음성을 다시 만들거나 음성 생성을 차단하지 않는다.
파일 무결성 통과가 정렬 통과나 최종 시청 승인을 뜻하지 않는다.

기준 파형 검사는 FFmpeg `silencedetect=noise=-38dB:d=0.12`를 사용한다. 에너지로
말과 쉼을 나누므로 짧은 숨·약한 잡음을 말로 잡거나 약한 발화를 놓칠 수 있다.
약한 짧은 소리에 대한 음향 특징은 추가 근거일 뿐, 실제 음절이 아니라는 확정은 아니다.
원래 기준의 측정값과 이런 소리를 제외한다고 가정한 참고값을 분리하며, 원래 경고를
참고값으로 지우지 않는다. 모호한 경계와 보간된 단어는 원본 음성을 들으며 확인한다.

## 자유 텍스트·앱 데모와 완성 트랙

텍스트 목소리와 확정된 앱 데모 대본은 문장·절 경계에서 짧게 나누어 합성한다.
인용문·등록된 복합 용어·식별자 안을 임의로 자르지 않는다. 각 청크에서 원문과
발음문을 따로 남기고, 기존 Whisper 내용·운율 검사와 후보 재시도를 적용한다.
사전에 없는 용어는 제작을 중단하거나 자동 등록하지 않고 실제 청크와 함께 청취
확인 대상으로 남긴다. 앱에서 고르는 여러 후보는 각각 독립된 전체 음성이다.
사람이 직접 적은 페이지 읽을 말은 대조할 원문이 없으므로 내용 자동 검사를 하지
않고 `not-checked`로 기록해 직접 듣고 고르게 한다.

강의의 선택 청크를 연결·2패스 정규화한 뒤에는 최종 WAV가 청크·갭·발화 신호를
그대로 담았는지 검사한다. 전체 갭은 발화 경계의 30ms만 제외하고 검사하며,
청크의 전체 파형뿐 아니라 발화가 있는 250ms 구간을 비교해 부분 유실을 찾는다.
원본과 완성 WAV의 샘플레이트가 다르면 비교할 원본을 FFmpeg의 오디오 리샘플러로
같은 샘플레이트에 맞춘다. 단순 선형 보간은 고주파 구간에서 정상 변환을 파형
손상으로 오인하므로 쓰지 않는다. 완성 WAV는 변형하지 않고 기존 유사도 기준을 유지한다.
정상 정규화·리샘플도 통과하는지는 기존 실제 강의 WAV 표본으로 재검한다.
그 WAV를 독립 Whisper로 다시 판독한다. 첫 후보 판정은
`quality.chunks`, 완성 트랙 검사는 `quality.finalTrack`에 따로 둔다. 명백한 WAV
무결성 실패는 제작 실패이며, 최종 재판독 차이는 완성 후 청취할 위치로 남긴다.
텍스트 목소리·앱 데모 후보도 최종 정규화 WAV의 조립 무결성을 확인하고
`qualityReview`와 `finalTrack`을 구분해 기록한다. 자동 검사 통과나 후보 선택은
전체 영상·연결부의 최종 청취 승인을 대신하지 않는다.
텍스트 후보의 자동 판정도 생성 당시 WAV 해시가 현재 파일과 일치할 때만 재사용한다.
해시가 없는 옛 후보는 자동 판정 기록이 있어도 `not-checked`로 낮춘다.
새 앱 데모 후보의 자동 판정은 생성 당시 WAV 해시가 현재 파일과 일치할 때만
표시한다. 파일이나 검사 기록이 달라지면 새 선택과 렌더를 막는다. 해시가 없는
옛 후보는 검사 불가로 표시하며, 렌더하면 직접 청취 경고를 남긴다.
후보를 만든 뒤 확정 대본이 바뀐 장면도 새 후보를 만들기 전에는 렌더하지 않는다.

앱의 새 제작은 기존 음성 캐시를 우회한다. 직접 실행하는 `course_pilot`의 클립
캐시는 WAV·부속 기록을 원자적으로 발행하고 전체 PCM·체크섬을 확인한 뒤에만
재사용한다. 불완전하거나 손상된 캐시는 새 합성 대상으로 본다.
같은 출력 폴더를 다시 쓸 때는 최신 실행 상태와 manifest의 `runId`가 일치해야
내보내기를 허용한다. 새 실행이 실패하면 이전 성공 파일을 남기되 현재 통과로
표시하지 않는다.
